⑥ 시스템 개요와 역할별 시나리오. 프로젝트 목표(고장 전에 정비 시점을 알려 긴급 정비를 계획 정비로)와 대시보드 흐름을 연결. 뒤에서 도는 분석: 비행 후 센서 데이터 → GRU 남은 수명 예측(90% 구간) → 위험 등급(빨강 40 이하, 노랑 80 미만) → 새로 "즉시 조치"가 된 엔진은 Slack으로 자동 알림(설정에서 끌 수 있음). 정비 담당자 로그인: 현황·알림에서 즉시 조치 엔진 확인 → 엔진 상세(남은 수명, 점검 예상 모듈) → 정비 계획에서 검토 시작, 결재 요청 → Slack 결재 알림. 운영 책임자 로그인: 결재함에서 요청 검증 → 승인 또는 반려(사유 기록) → Slack 알림(승인·반려·정비 완료) → 정비 효과·주간 리포트 확인. 권한: 담당자는 검토·결재 요청·회수·정비 완료, 책임자만 승인·반려(대시보드 plan 권한 규칙). 이 부분이 Human-in-the-Loop(결정은 사람)에 해당하고 AX 설계 부분. 주의: 로그인은 서버 없는 시연용 가짜 계정이며 보안 기능이 아님. Slack 알림은 서버 함수와 웹훅(SLACK_WEBHOOK_URL)이 연결돼야 동작하고, 연결 안 된 시연 환경에서는 "미연결"로 표시됨. 모바일은 Slack 앱 푸시를 이용하는 것이며 실제 휴대폰 수신은 발표 전 확인할 것. 화면의 가동중단·비용 금액은 가정 기반 시뮬레이션. 실제 정비 이력 입력과 오탐·놓침 피드백으로 모델을 다시 맞추는 루프는 아직 없음(다음 단계). 분기: 책임자가 승인하면 정비 일정이 확정되고 담당자가 정비 후 정비 완료 처리, 정비 효과·주간 리포트로 확인. 반려하면 사유를 기록하고 담당자가 수정해 다시 결재 요청(반려 상태에서 재요청 가능). 승인·반려·정비 완료·결재 요청 때마다 Slack 알림(연결 시). Slack은 부가 기능이라 강조하지 않아도 됨.
